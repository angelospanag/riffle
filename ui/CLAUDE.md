# UI — Riffle Next.js app

Next.js 16 App Router SPA. A reading-focused RSS client with a 3-column layout: feeds → post list → reading pane.

## Stack

| Concern | Library |
|---|---|
| Build | Next.js 16 (Turbopack) + TypeScript 7 |
| UI framework | React 19 |
| Styling | Tailwind CSS v4 (`@tailwindcss/postcss` — see `postcss.config.mjs`, easy to forget) |
| Data fetching | TanStack Query v5, via hey-api's generated `queryOptions`/`mutationOptions` — no hand-written query hooks |
| API client | `@hey-api/client-next` + generated `client/` from `../api/openapi.yaml` |
| Icons | lucide-react |
| Package manager | **bun** — do not use npm or yarn |

│   ├── client.gen.ts          hey-api client instance (configured in providers.tsx)

├── components/
│   ├── Home.tsx               Top-level layout: header + 3 columns (FeedSidebar, PostList, PostReader)

│   ├── PostList.tsx           Column 2 — post list, unread filter, pagination; click selects (doesn't expand)

## Brand tokens

Defined in `app/globals.css` `:root` — **dark by default**, with a `prefers-color-scheme: light` override block.
Always use these — don't hardcode hex values.

| Token | Dark (default) | Use |
|---|---|---|
| `--color-bg` | `#0f1115` | Page background |
| `--color-surface` | `#161922` | Sidebar, headers, expanded post background |
| `--color-surface-hover` | `#1e2230` | Hover state on rows/buttons |
| `--color-border` | `#262b38` | All borders (`* { border-color: var(--color-border) }`) |
| `--color-text` / `--color-text-muted` | `#e5e7eb` / `#8b93a7` | Primary / secondary text |
| `--color-accent` / `--color-accent-hover` | `#6366f1` / `#818cf8` | Indigo — links, unread markers, primary actions |
| `--color-accent-soft` | `#201f3d` | Tinted background for selected sidebar item / unread badge |
| `--font-body` | Inter | UI chrome (sidebar, buttons, meta text) |
| `--font-serif` (`.font-serif-content`) | Source Serif 4 | Post titles and article body — editorial, reading-focused |

`--color-accent` is used both as a solid badge/button background (white text on top) and as a plain text/link color
on a soft background — keep it a value that has reasonable contrast both ways (indigo-500-ish) rather than
splitting it into two tokens.

Unread state is a left accent bar (`border-l-2 border-l-[var(--color-accent)]`) on feed rows and post rows — a quiet
indicator rather than a solid fill.

## Data layer

No hand-written query hooks — components call the generated `xOptions()`/`xMutation()` functions from
`client/@tanstack/react-query.gen.ts` directly:

```tsx
const { data } = useQuery(listFeedsOptions());
const createFeed = useMutation({
  ...createFeedMutation(),
  onSuccess: () => queryClient.invalidateQueries({ queryKey: listFeedsQueryKey() }),
});
```

hey-api generates the fetch/queryKey plumbing; cache invalidation on mutations is the only thing we still write by
hand (the generator has no way to know that marking a post read should also invalidate the feed list's unread
counts). Query keys are objects shaped `[{ _id: "listPosts", ...params }]` — invalidate broadly across params with
a partial key like `queryClient.invalidateQueries({ queryKey: [{ _id: "listPosts" }] })`.

Mutation errors are already typed concretely (e.g. `createFeedMutation()` types its error as the API's `ErrorModel`,
not `unknown`), so read `mutation.error?.detail` directly — no wrapper needed.

## Reading pane content

`PostReader.tsx` renders `post.content || post.description` as HTML (`dangerouslySetInnerHTML`, wrapped in
`.prose-content`), never as plain text. Feeds put markup in either field — some feeds' `<description>` is nothing
but an `<img>` tag, with no `<content:encoded>` at all — so treating `description` as plain text would render a
literal `<img src=...>` string instead of an image. `.prose-content img` in `globals.css` caps images to
`max-width: 100%`.

Feed favicons (`FeedSidebar.tsx`'s `FeedIcon`) render `feed.favicon_url` — resolved server-side by the API during
refresh (`api`'s `discoverFaviconURL`, which parses the site's `<link rel="icon">` tag and falls back to
`{origin}/favicon.ico`) — falling back client-side to the same `{origin}/favicon.ico` guess for feeds not yet
refreshed, then to a generic RSS icon on load error via `<img onError>`.

The reading pane's body text size is user-adjustable (`PostReader.tsx`'s `useReaderFontSize`) via A-/A+ buttons —
an inline `rem` value applied to the `.prose-content` wrapper, persisted to `localStorage`
(`riffle:reader-font-size-rem`) so it survives reloads. `.prose-content`'s spacing (`globals.css`) is written in `em`
units specifically so it scales proportionally with this rather than staying fixed.

## API proxy

`app/api/[...path]/route.ts` is a Route Handler that forwards all `/api/*` requests to the Go backend, for every
HTTP method the API uses (GET/POST/PUT/PATCH/DELETE) — unlike a read-only proxy, this one forwards the request body
too. **The Go routes themselves are unprefixed** (`/feeds`, `/posts`, ...), so the proxy strips the `/api` prefix
before forwarding: `${API_URL}/${path}`, not `${API_URL}/api/${path}`.

| Context | Setting |
|---|---|
| Dev | Default: proxies to `http://localhost:8080` |
| Podman Compose | Set `API_URL=http://api:8080` in the service environment |
| Production | Set `API_URL=https://your-api-host` |

`API_URL` is a server-side env var (no `NEXT_PUBLIC_` prefix). The browser always uses relative `/api/*` paths; the
hey-api client is configured with `baseUrl: "/api"` in `providers.tsx`.

Adding a feed validates the URL is a parsable RSS/Atom feed server-side (`api`'s `create-feed` handler) and returns
`422` with a `detail` message on failure — `FeedSidebar.tsx`'s add-feed form reads `mutation.error?.detail` straight
from the generated mutation to display it.

## Dev

```bash
cd ui
mise install      # first time only: pinned tools
mise run install  # first time only: dependencies
mise run dev      # http://localhost:3000
```

The Go API must be running on `:8080`.

The container image (`Containerfile`) runs as non-root (uid 65532) on port 3000. Its app files are owned by that uid so Next can write `.next/cache`.

## Common tasks

```bash
mise run dev        # Next.js dev server
mise run build       # production build (standalone output)
mise run typecheck   # tsc --noEmit
mise run lint        # Biome check
mise run fmt         # Biome format --write
mise run vuln        # bun audit — scan dependencies for known vulnerabilities
mise run generate    # regenerate client/ from ../api/openapi.yaml
```

## Adding a new API-backed feature

1. Add/change the Huma route in `api/`, then run `mise run generate` (from repo root) to regenerate
   `api/openapi.yaml` and `ui/client/`.
2. Use the newly generated `xOptions()`/`xMutation()` from `client/@tanstack/react-query.gen.ts` directly in the
   component with `useQuery`/`useMutation`, adding `onSuccess` invalidation as needed.
3. Never hand-edit anything under `client/` — it's regenerated, not edited.
